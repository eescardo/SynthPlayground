# Where this review style comes from

## Scope and limits

Research snapshot: 2026-09-27, `eescardo/SynthPlayground`, before adding these skills. All 101 PRs returned by paginated GitHub REST listing were inventoried: 96 merged, three open (#90, #103, #104), and two closed unmerged (#68, #75). The numbering has gaps (#86, #94, #96); they were not returned as PRs. The retained histories contain 1,169 commit entries. See the [per-PR progression ledger](pr-history.md).

Read all retained commit subjects and PR conversation comments, checked the initial-to-final changed-file/stat progression for every PR, retrieved every PR's final file diffs, and inspected representative implementation/review-fix hunks behind the themes below. This is a history synthesis, not a claim to have independently re-reviewed every line of all 1,169 commits.

The GitHub review and inline-review-comment endpoints returned **zero formal reviews and zero inline comments**. There were 102 issue-style comments: 66 workflow-bot posts and 36 posts from the repository owner's account, mainly follow-up summaries. Those posts can themselves have been agent-authored; account identity is not proof of who formulated feedback. Reviews copied between private tasks are not in this dataset. Do not invent their text or attribute every later commit to a human review request.

“First” means the first retained PR commit, not a recoverable original submission if history was rewritten. “Final” means the last retained PR head; the ledger separately links landed merge commits. Concurrent main-branch updates can make whole trees differ, so use the PR merge delta for landed behavior, not an unqualified whole-tree head/merge comparison. A one-commit PR has no observable internal evolution. Open and unmerged PRs are context, not evidence of accepted final design.

## Lessons from the longer revisions

- **#21, #25, #31, #97, #99 — edits must preserve the entire musical model.** Clipboard and timeline edits evolved to preserve automation, markers, scope, and composition end semantics. Later naming/extraction commits made the rules easier to see. Review the resulting project and undo/serialization paths, not only the gesture handler.
- **#47–50, #58, #61, #93, #95 — audio architecture is about explicit boundaries and ownership.** Render streams/factories, planning caches, binary asset handoff, engine pooling, and lifecycle APIs evolved separately. Hoisting work out of hot paths is valuable only if state reuse, cancellation, and cleanup remain correct. JS fallback paths were subsequently removed; early dual-backend structure is historical context.
- **#62–63 — schema changes reach farther than the visible control.** Units, macro ranges/curves, host ports, compiler behavior, normalization, preset versions, and module-face math had to agree. The [preset-version correction](https://github.com/eescardo/SynthPlayground/pull/63#issuecomment-4359785231) explicitly distinguishes schema migration from bundled preset updates.
- **#85 — review can simplify while fixing correctness.** The spectrum review-fix commit `2001505051` removed redundant full-resolution/JS work while correcting final capture behavior. Later work split graph families, merged incremental captures through helpers, bounded failure retries, and coalesced drag commits. Do not preserve obsolete implementation scaffolding just because it has tests.
- **#69–70, #87, #89, #102 — ownership must continue through the UI boundary.** Splitting global files and grouping one call site were intermediate steps. Local CSS, narrow child contracts, and semantic selector hooks made boundaries usable. Refactors still needed interaction regression checks.

## What the history does not justify

Do not promote iterative pixel tweaks, one rejected experiment, closed-unmerged scaffolding (#68), or a superseded preset PR (#75) into universal design rules. Do not require broad architecture work on every review, compatibility for never-shipped intermediate states, arbitrary extraction by line count, or tests for every trivial rename. The review bar is a concrete benefit to correctness, maintainability, readability, or polish in the current PR's scope.
